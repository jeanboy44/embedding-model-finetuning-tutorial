# 강의 계획: 임베딩 모델 파인튜닝

부제: AI 시대 생존법: 내 업무 확장편

> 이 저장소의 모든 자료(튜토리얼, 스크립트, 문서)는 이 흐름을 따른다.
> 새 작업을 시작하는 에이전트는 이 파일을 먼저 읽고, 만드는 것이 아래 4단계 중 어디에 속하는지 확인한다.

## 핵심 메시지

데이터 사이언티스트(DS)의 본업은 모델을 고르고, 학습하고, 평가하는 일이다.
예전에는 그 모델을 "쓸 수 있게" 만드는 일(API, 배포 최적화, 도구, 화면)은 다른 직군의 몫이거나, DS가 억지로 떠안는 부담이었다.
AI 코딩 도구가 오면서 DS 한 사람이 그 범위까지 직접, 빠르게 해낼 수 있게 됐다.
강의는 **같은 임베딩 모델 하나를 들고 DS의 업무 범위가 단계별로 넓어지는 과정**을 보여 준다.

```
[1. DS 본업]      모델 비교 → 학습 → 평가
      ↓
[2. +α 업무]      API로 감싸서 남이 쓰게 하기
      ↓  ── AI가 오면서 ──
[3. 배포 최적화]  ONNX 변환 · 양자화 · 속도/정확도 비교
      ↓
[4. 제품화]       CLI 도구 배포 · React 프론트엔드
```

주제 도메인은 대한민국 법령 조문 검색이다(데이터 결정은 `docs/handoff-law-question-gen.md` 참고).

## 단계별 내용

### 1단계. DS 본업: 모델 비교, 학습, 평가

기존 DS로서 해 왔던 일. 강의의 기준점이다.

- 베이스 모델 비교: `intfloat/multilingual-e5-small` 등 후보 임베딩 모델을 같은 평가셋으로 비교 (`docs/adr/001-model-selection.md`)
- 데이터 준비: legalize-kr 법령 코퍼스 (`scripts/prepare_law_data.py`), Claude 스킬로 질문·정답 조문·hard negative 생성 (`.claude/skills/law-question-gen/`)
- 파인튜닝: MNRL + `BatchSamplers.NO_DUPLICATES`, e5 접두어는 코드에서 붙인다
- 평가: Recall@k, MRR, nDCG로 Base vs Fine-tuned 비교 (필요하면 LLM 쿼리 확장도 비교군으로)
- 관련 위치: `tutorials/phase1_model_dev/`, `src/embeddings/`, `src/models/`

### 2단계. +α로 떠안던 일: API 개발

모델을 만든 뒤 "그래서 어떻게 써요?"라는 요청에 답하려고 DS가 추가로 해야 했던 일.

- 학습한 모델을 검색 API로 감싸기 (예: FastAPI `POST /search` → 상위 k개 조문 반환)
- 요청/응답 스키마, 모델 로딩, 간단한 헬스체크
- 메시지: 예전에는 이 단계가 DS에게 낯설고 시간이 많이 드는 일이었다
- 관련 위치: `src/retrieval/`, (신규) API 모듈

### 3단계. AI가 오면서: 배포 최적화

AI 도구 덕분에 DS가 직접 손대기 쉬워진 영역 ①.

- PyTorch 모델 → ONNX 변환
- 양자화(동적 INT8 등)
- 원본 / ONNX / 양자화 모델의 **지연 시간·메모리·모델 크기·검색 정확도** 비교표
- 메시지: "정확도를 얼마나 잃고 얼마나 빨라지는가"를 DS가 직접 재고 판단한다
- 관련 위치: (신규) 변환·벤치마크 스크립트

### 4단계. AI가 오면서: CLI 도구와 프론트엔드

AI 도구 덕분에 DS가 직접 손대기 쉬워진 영역 ②. 모델을 "제품"으로 전달한다.

- CLI 도구 개발 및 배포: 동료가 설치해서 바로 쓰는 검색 도구 (cyclopts, `uvx`로 실행)
- React 프론트엔드: 질문을 넣으면 관련 조문을 보여 주는 검색 화면 (2단계 API 호출)
- 메시지: DS 한 사람이 모델부터 사용자 화면까지 끝까지 만든다
- 관련 위치: `src/cli/`, (신규) 프론트엔드 폴더

## 기존 Phase 구성과의 관계

`README.md`의 Phase 1~4(모델 개발 / CLI & MCP / RAG 에이전트 / 모니터링)는 이 계획 이전의 구성이다.
강의 흐름은 위 4단계를 기준으로 하며, 기존 Phase 자료는 해당 단계로 재배치하거나 보조 자료로 둔다.
README 개편은 아직 하지 않았다.
