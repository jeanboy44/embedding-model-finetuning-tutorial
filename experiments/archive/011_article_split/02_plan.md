# 011 조 단위 분할 — 2. 실험 계획 (초안, 실행 전)

2026-10-11 사용자와 정리한 계획이다. 아직 돌리지 않았다. 강의 5~8교시 숫자와 장표는 이 실험과 상관없이 그대로 둔다.

## 왜 하나

강의 시나리오(설비 매뉴얼 검색)의 운영 방식은 "매뉴얼 전체로 학습하고, 매뉴얼이 추가되면 다시 학습"이다. 매뉴얼은 자주 바뀌지 않는다.

지금의 법령 단위 분할(001 등)은 **처음 보는 매뉴얼**에서의 점수를 잰다. 이 운영 방식에서는 현업이 신경 쓰지 않는 숫자이고, 법령에만 나오는 말은 배울 기회가 없어 낮게 나온다.

현업이 궁금한 건 **"학습한 매뉴얼 안에서, 작업자가 실제로 치는 말로 찾아지나"**다. 그런데 매뉴얼 전체를 학습해도 생성 질문이 모든 절에 붙지는 않는다. 지금 데이터도 검색 문서 25,967개 중 정답으로 쓰인 문서는 9,704개(약 3분의 1)다. 그래서 실제 질문의 상당수는 "학습한 매뉴얼 안의, 학습 질문이 없던 절"을 묻는다. 조 단위 분할은 이걸 잰다.

| 분할 | 재는 것 | 문제 |
|---|---|---|
| 질문 단위 | 학습한 절을 다른 말로 물을 때 | 같은 조문 · 같은 LLM · 같은 가이드로 만든 질문끼리 닮아 점수가 부풀어 오른다 (질문 단위로 섞으면 test 질문의 64.6%가 정답 조문이 train에도 나온다, `02_split.py`) |
| **조 단위 (이번)** | **학습한 매뉴얼 안의, 처음 보는 절** | 법과 시행령이 비슷한 문장을 되풀이하는 누수가 남는다 (아래에서 잰다) |
| 법령 단위 (지금) | 처음 보는 매뉴얼 | 운영 방식과 안 맞고, 법령 고유의 말은 배울 수 없다 |

검토했지만 이번에 하지 않는 대안: 별도 에이전트가 조문을 보지 않고 질문을 먼저 쓰고 정답은 나중에 판정하는 "실제 검색어 대용" 평가셋. 실제 검색어가 없을 때의 최종 보고용으로는 의미가 있지만, 이번 질문(조 단위 분할)에는 필요 없다.

## 가설

- **H1:** 조 단위 test에서, 조 단위 train으로 학습한 모델(011)이 학습 전 e5(000)보다 R@5가 높다.
- **H2 (매뉴얼을 학습에 넣은 효과):** 같은 조 단위 test에서 011이 001_baseline(법령 29개만 학습)보다 높다. 차이는 001이 학습 때 못 본 법령의 질문에서 크다.

## 고정한 것

| 항목 | 값 |
|---|---|
| 데이터 | 지금 질문 v1 12,232개와 코퍼스 25,967문서 그대로. **새로 만들지 않는다** |
| 시작 모델 | intfloat/multilingual-e5-small |
| 학습 설정 | `experiments/001_baseline/config.yaml`과 같음: CachedMNRL mini 16, 배치 32, lr 2e-5, warmup 0.1, 최대 epoch 3, 길이 512, negative 1개, seed 42, NO_DUPLICATES |
| 검색 범위 | 평가는 코퍼스 전체 25,967문서에서 |
| 바꾸는 것 | 분할 방법 하나: 법령 단위 → 조 단위 |

## 분할

- 묶음 단위: 정답 문서의 `parent_id`(조). 긴 조문을 항 · 호로 자른 조각에는 같은 법령 이름과 조 제목이 붙어 있으므로, 같은 조의 조각은 반드시 한쪽으로 보낸다.
- 비율: test 15%, dev 10%, 나머지 train. seed 42. 법령마다 test · dev가 생기도록 법령별로 층화한다.
- 가상 분할(층화 없이, 2026-10-11 계산)로 본 규모: 정답이 붙은 조 5,941묶음 → train 9,190 · dev 1,198 · test 1,844 질문. 법령 단위 분할(8,294 · 1,412 · 2,526)과 비슷하다.

## 누수 방지

1. **hard negative에서 dev · test 문서를 뺀다.** train 질문의 hard negative 16,557개 중 1,972개(11.9%)가 dev · test 문서다. 그대로 두면 test 정답 절이 학습 때 오답으로 나온다(002에서 같은 종류의 문제를 잡은 적이 있다: 캐낸 오답 후보의 15~19%가 평가용 법령 문서).
2. 빼고 나면 388개 질문(train의 4.2%)은 hard negative가 하나도 남지 않는다. 이 질문은 배치 안의 다른 정답(31개)만 오답으로 쓰고 학습한다. 다시 캐지 않는다.
3. **법 ↔ 시행령 비슷한 문장:** test 정답 문서마다 가장 비슷한 train 정답 문서와의 유사도(학습 전 e5 코사인, 글자 3-gram 자카드)를 잰다. 분포를 기록하고, 상위 구간(예: 코사인 0.95 이상)을 뺀 test로도 따로 보고한다.
4. **질문 중복:** test 질문마다 가장 비슷한 train 질문과의 유사도를 같은 방식으로 재서 기록한다.
5. dev 복수 정답 판정 파일(`data/labels/dev.jsonl`)은 법령 단위 dev에 대한 것이라 쓰지 않는다. 판정은 doc(조각)과 article(같은 조)만 쓴다.

## 지표와 판정 기준

- 주요 지표: test doc R@5. 보조: article R@5, R@1 · R@10, MRR@10, 말투별(keyword · question · situation), 법령 평균.
- epoch 선택은 dev(학습 중 간이 dev R@5)로만 한다. test는 마지막에 한 번만 쓰고 `experiments/ledger.tsv`에 적는다.
- H1 · H2 "개선": Δ ≥ 0.02, 그리고 질문 단위 대응 bootstrap 95% CI 하한 > 0, McNemar p < 0.05 (두 비교에 Holm 보정).
- H2는 test 질문을 "001이 학습한 법령(train 29개)"과 "001이 못 본 법령(dev · test 25개)"으로 나눠서도 본다.
- 주의: 011의 조 단위 test 점수와 001의 법령 단위 test 점수(0.669)는 test가 달라 직접 비교하지 않는다.
