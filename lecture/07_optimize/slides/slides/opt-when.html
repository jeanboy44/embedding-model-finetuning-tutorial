문서를 대량으로 자주 다시 임베딩처리량 (문서/초)GPU · 배치. 줄인 모델이 더 느릴 수도

아직은 아닐 때 정확도가 목표에 못 미칠 때, 사용자가 적은 내부 실험, GPU 서버가 이미 넉넉할 때. 줄이기는 정확도를 지킬 때만 의미가 있다.

그럼 언제 필요할까요. 모델이 어디에 놓이느냐가 정합니다. 동료 노트북이나 사내 PC에 CLI로 깔아 준다면 설치 크기와 모델 파일이 문제라 torch를 빼는 ONNX 변환과 어휘 가지치기가 먼저입니다. GPU 없는 CPU 서버라면 메모리와 지연이, 요청에 따라 서버를 자주 켰다 껐다 한다면 로딩 시간이, 서버를 여러 대 띄운다면 메모리, 곧 서버 비용이 문제입니다. 반대로 문서를 대량으로 자주 다시 임베딩해야 한다면 처리량이 중요한데, 이때는 줄인 모델이 오히려 느릴 수 있어서 GPU와 배치 크기를 먼저 봅니다. 이건 뒤 비교표에서 숫자로 확인합니다. 아직 최적화할 때가 아닌 경우도 있습니다. 정확도가 목표에 못 미친다면 줄이기보다 정확도가 먼저고, 사용자가 적은 내부 실험이나 GPU가 넉넉한 환경이라면 굳이 할 필요가 없습니다. 오늘은 이 중 우리 상황, 즉 동료에게 CLI로 깔아 주고 CPU 서버에 API로 띄우는 경우를 기준으로 줄여 봅니다.
