단계2022에 하던 방식시간이 새는 곳
② 데이터사람이 질문을 쓰거나 외주 라벨링, 라벨링 도구 개발도구 화면 다듬기, 가이드 맞추기, 작업자마다 다른 질문 품질

④ 에러분석틀린 질문을 하나씩 열어 엑셀에 분류수백 건 읽기, 분류 기준이 날마다 흔들린다
⑤ 공유 · 보고표와 그래프를 손으로, PPT · Notion에 직접 작성숫자 옮겨 적고 장표 모양 다듬기, 실험이 바뀌면 처음부터 다시 쓴다
단계별로 보면 이렇습니다. 데이터는 사람이 쓰거나 외주로 라벨링을 맡기고, 그러려면 도구를 만들어야 합니다. 시간은 도구 화면을 다듬고 가이드를 맞추는 데 갑니다. 학습 실험은 새 방법이 떠오르면 직접 구현하고, 무엇을 잴지와 기록하는 코드도 실험마다 새로 짭니다. 그러다 보니 구현이 귀찮은 방법은 미루게 되고, 실험마다 재는 기준이 조금씩 달라져 나중에 비교가 어려워집니다. 분석은 틀린 질문을 하나씩 열어 엑셀에 분류합니다. 수백 건을 읽다 보면 어제 분류 기준과 오늘 기준이 달라집니다. 공유와 보고는 표와 그래프를 손으로 만들어 PPT나 Notion에 직접 씁니다. 로그에서 숫자를 옮겨 적고 장표 모양을 다듬는 데 시간이 가고, 실험이 하나 바뀌면 보고서를 처음부터 다시 고쳐야 합니다. 1교시 표현으로 하면, 내가 맡는 범위는 모델과 API 두 칸인데 그 두 칸 안에서도 이렇게 손이 많이 갔습니다.

그럼 2022년에 제 시간은 실제로 어디에 갔을까요. 세 군데입니다. 첫째, 도구를 만들고 고치는 일. 라벨링 화면, 검수 화면, 작업자 계정, 저장할 DB. 작업자가 쓰다가 막히면 그때마다 버그를 고치고 화면을 다듬습니다. 둘째, 데이터 손질. 법령 사이트에서 조문을 긁어 엑셀로 정리하고, 모델이 못 읽는 긴 조문은 손으로 자르고, 라벨 형식을 맞추고, 작업자마다 기준이 달라 가이드를 고치는 회의를 합니다. 셋째, 실험 뒤치다꺼리. 설정을 바꿀 때마다 파일을 복사해 고치고, 밤새 돌린 run이 죽어 있으면 원인을 찾아 다시 띄우고, 로그에서 숫자를 엑셀로 옮겨 표와 그래프, 보고서를 만듭니다. 그러다 보니 정작 중요한 실험, 가설을 세우고 돌리고 틀린 질문을 보고 다음을 정하는 그 바퀴는 과제 기간 내내 손에 꼽을 만큼밖에 못 돕니다. 학습을 기다리는 시간은 제 시간을 뺏지는 않지만, 하루에 돌 수 있는 바퀴 수를 막습니다. 1교시에 본 하루 두세 바퀴, 그것도 잡일을 하고 남는 시간에 말이죠.

2026년에도 도구는 필요합니다. 달라진 건 누가 만드느냐입니다. 2022년의 라벨링 도구 자리에는 Claude 스킬 하나가 들어갑니다. 질문 규칙을 스킬에 적고, 서브에이전트 12개가 법령 파트 230개를 나눠 질문을 만들었습니다. 파트 하나에 1~7분, 모두 1만 2천 개입니다. 오늘 실습에서 여러분도 파트 하나를 직접 만들어 봅니다. 라벨 확인 도구 자리에는 검증 스크립트와 판정 에이전트가 들어갑니다. 형식과 정답 조문이 실제로 있는지는 스크립트로 확인하고, 헷갈리는 오답 후보 9,009쌍이 진짜 오답인지는 판정 에이전트 30개가 나눠 판정했습니다. 같은 쌍을 다른 에이전트가 다시 판정해 기준이 맞는지도 쟀습니다. 실험 스크립트는 설정 파일 한 장으로 학습, 평가, 기록이 한 번에 되고, 오답 채굴이나 실패 유형 집계 같은 곁다리 도구는 필요할 때 말로 시켜 만들었습니다. 결과 정리는 run마다 실험 장부에 한 줄씩 남고, Claude가 그걸 종합해 HTML 보고서로 씁니다. 2022년 장과 같은 네 칸인데, 전부 필요할 때 에이전트가 만듭니다.
