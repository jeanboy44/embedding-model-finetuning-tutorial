질문도 문서도 PC 밖으로 나가지 않는다. 대신 모델과 문서 전체가 파일 안에 들어 있다.

데스크톱 앱의 환경은 단순합니다. 화면, 모델, 조문 벡터와 원문이 전부 사용자 PC 안에 있습니다. 질문이 들어오면 PC 안에서 모델이 벡터로 바꾸고, PC 안의 조문 벡터와 비교합니다. 서버가 없으니 인터넷이 끊겨도 돌고, 질문이 밖으로 나가지 않습니다. 대신 뒤집어 말하면 모델과 문서 전체가 사용자 손에 들어간다는 뜻입니다. 그리고 무언가를 바꾸려면 파일을 다시 나눠 줘야 합니다. 이 두 가지가 뒤에 나오는 장단점의 뿌리입니다.

이 과제에서는 다루지 않는다. 사용자가 겪는 일은 HTML 파일 하나와 같다. 받아서 열면 내 PC에서 돈다. 스택이 더해 주는 것은 설치 · 자동 업데이트 · 파일 접근 같은 앱 기능이다.

원래 데스크톱 앱을 만들려면 다른 스택을 씁니다. Electron은 웹 기술로 화면을 만들고 크롬을 통째로 넣어서 설치 파일이 보통 80에서 150MB입니다. Tauri는 운영체제에 이미 있는 웹뷰를 쓰고 핵심은 Rust라서 10MB 안팎으로 작습니다. 사내 윈도우 앱이라면 C#으로 WPF나 WinUI를 쓰고, 모델은 Microsoft.ML.OnnxRuntime으로 돌립니다. 7교시에 C# 앱 안에 넣으려면 ONNX가 필수라고 했던 게 이 경우입니다. 파이썬 코드를 그대로 PyInstaller로 묶을 수도 있지만 torch가 들어가면 수백MB에서 GB가 되니, 역시 7교시처럼 ONNX로 바꿔 넣습니다. 오늘은 이 스택들은 다루지 않습니다. 사용자 입장에서 겪는 일은 HTML 파일 하나와 같기 때문입니다. 받아서 열면 내 PC에서 모델이 돕니다. 스택이 더해 주는 건 설치 프로그램, 자동 업데이트, 내 PC 파일 읽기 같은 앱 기능입니다. 설치 크기는 2026년 기준 흔히 보이는 범위이고, 모델 크기는 따로 더해집니다.

Chrome, Safari, Firefox에서 file://로 열어 바깥 요청이 없는 것까지 확인했습니다. 만드는 방법은 apps/offline-search README에 있습니다.

ragkit-search skill install

모델이 박힌다

--checkpoint를 주고 설치하면 명령에 그 모델이 들어가, 에이전트가 그 모델로 검색한다

방금 만든 CLI를 사람만 쓰는 게 아니라 에이전트도 쓰게 하는 가장 가벼운 방법이 에이전트 스킬입니다. SKILL.md 파일 하나에 이름, 언제 쓰는지 적은 설명, 쓸 명령, 순서를 적습니다. 에이전트는 평소엔 이름과 설명만 보고 있다가, 법령 질문이 오면 파일 전체를 읽고 그 순서대로 CLI를 부릅니다. 순서는 이렇습니다. 사용자 말 그대로 한 번 검색하고, 필요하면 법률 용어로 바꿔 다시 찾고, show --article로 조문 원문을 읽은 뒤, 조문 id를 붙여 답합니다. 설치는 저장소 루트에서 uv run --package ragkit-search ragkit-search skill install 한 줄이고, --agent claude면 .claude/skills/, gemini면 .gemini/skills/에 들어갑니다. --user를 주면 홈 폴더에 설치돼 내 모든 프로젝트에서 씁니다. 스킬 안의 명령 앞부분은 설치할 때 이 저장소를 가리키는 uv run 명령으로 채워져서, 에이전트가 어느 폴더에서 불러도 같은 모델과 인덱스를 씁니다. Claude Code와 Gemini CLI가 같은 형식을 읽는다는 점이 좋습니다. 그리고 --checkpoint로 파인튜닝 모델을 주고 설치하면 명령 자체에 그 모델이 박혀서, 에이전트는 신경 쓰지 않아도 그 모델로 검색합니다. 이걸로 다음 장의 비교를 했습니다.
