도구 설계

도구 설명이 곧 사용 설명서다

search_laws의 설명 (에이전트가 읽는 글)

질문과 의미가 가까운 한국 법령 조문 조각을 찾는다. 조 전체가 필요하면 id로 get_article을 부른다.

laws: 검색할 법령의 정확한 이름 목록 (list_laws로 확인). 비우면 전체.

이름 · 설명 · 입력 스키마를 보고 에이전트가 언제 무엇을 부를지 정한다

틀린 입력은 이유를 돌려준다. laws=["근로기준"] → "비슷한 이름: 근로기준법 …"

읽기 전용으로 표시해 에이전트가 안심하고 부른다

MCP 서버를 만들 때 코드보다 신경 쓸 곳은 도구 설명입니다. 앞에서 본 SKILL.md와 같은 역할이죠. 에이전트는 이 글을 읽고 언제 어떤 도구를 부를지 정합니다. 예를 들어 search_laws 설명에 "조 전체가 필요하면 get_article을 부른다"고 써 두면 에이전트가 그 순서로 움직입니다. 잘못된 입력에는 왜 틀렸는지 돌려줘야 에이전트가 스스로 고쳐서 다시 부릅니다. 03_mcp_server.py에서 법령 이름을 "근로기준"으로 틀리게 넣으면 "비슷한 이름: 근로기준법 …"이 돌아오는 걸 직접 보실 수 있습니다. 스킬의 CLI도 같은 안내를 stderr로 줍니다. Claude Code · Claude Desktop 등록 명령은 03_mcp_server.py가 이 컴퓨터의 경로를 채워 마지막에 출력하니, 그대로 복사해 씁니다.
