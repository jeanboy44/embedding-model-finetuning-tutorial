장점

단점

연결된 서버의 도구 설명이 요청마다 문맥을 차지한다

서버를 등록 · 실행 · 관리한다

규격이 빠르게 바뀐다 (2026-07 개정: 세션 제거)

주의할 점

도구 결과 속 숨은 지시를 따를 수 있다 (프롬프트 인젝션)

원격이면 인증(OAuth)이 필수

읽기만 하는 도구는 읽기 전용으로 표시한다

MCP의 장점은 표준 형식입니다. 도구마다 이름, 설명, 입력 스키마가 정해져 있어서 MCP를 지원하는 앱이면 어디든 붙고, Claude Desktop처럼 셸이 없는 채팅 앱에서도 씁니다. 서버를 HTTP로 원격에 두면 사용자는 설치 없이 주소만 등록하고, 업데이트도 서버 한 곳에서 합니다. 웹 배포의 장점이 그대로 옵니다. 단점은 연결해 둔 서버의 도구 설명이 요청마다 문맥에 올라간다는 겁니다. 도구가 많은 큰 MCP 서버는 이것만 수만 토큰이라, 쓰지도 않는데 비용과 문맥을 먹습니다. 우리 서버는 도구가 넷이라 작습니다. 서버를 등록하고 실행 관리해야 하고, 규격도 빠르게 바뀝니다. 2026년 7월 개정에서는 세션 개념이 빠지는 큰 변경이 있었습니다. 주의할 점으로, 도구가 돌려준 글 안에 숨은 지시가 있으면 에이전트가 따를 수 있습니다. 프롬프트 인젝션이죠. 원격 서버라면 인증이 필수이고 규격은 OAuth를 씁니다. 그리고 검색처럼 읽기만 하는 도구는 읽기 전용으로 표시해 두면 에이전트와 사용자가 안심하고 부릅니다.
