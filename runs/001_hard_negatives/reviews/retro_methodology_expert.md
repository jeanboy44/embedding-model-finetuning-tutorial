# 001 결과·회고 검토 — 실험 방법론

결론: **A, B, C 모두 대조군보다 낫다는 판정은 타당하다.** 다만 "A가 최고", "출처 3/4·개수 1/4", "seed 범위 0.0014로 확신" 같은 문장은 근거보다 강하다. 아래 수치는 `03_run/*/eval_dev.json`으로 다시 계산했다.

## 1. 결정 규칙 적용과 보고

- **Holm 보정은 맞게 적용됐다.** 원래 p값에 순서대로 3, 2, 1을 곱했고(A 1.7e-6 → 5.2e-6, B 2.0e-4 → 4.0e-4, C 4.9e-4 → 4.9e-4), 단조성도 유지된다.
- **seed 범위 0.0014는 seed 분산을 크게 과소추정한다.**
  - 대조군 seed끼리 top-5 적중이 갈리는 질문이 58~72개(4~5%)다. 0.0014는 질문 2개 차이일 뿐이고, 질문별로 뒤집힌 것이 우연히 상쇄된 결과다.
  - 뒤집힘이 무작위라고 보면 R@5의 seed SD는 √(0.047/1412) ≈ **0.006**이다.
  - 따라서 "Δ > 범위" 기준은 사실상 아무것도 거르지 않는다. 이 기준은 "Δ > 2×0.006"으로 바꿔야 한다.
  - A·B·C의 Δ(+0.031~+0.041)는 이 기준도 넘는다. 결론은 유지된다.
  - B 대 A(−0.005)와 C 대 A(−0.010)는 seed 잡음 1~2 SD 안이다. 단일 seed로는 구분할 수 없다.
- **비교 기준선이 섞였다.** 같은 표에 대조군이 둘 쓰인다.
  - 대조군 평균 기준: Δ(+0.041), 법령 평균(0.739)
  - seed 42 기준: CI [+0.023, +0.056](Δ +0.040에 해당), 나빠진 법령 수
  - 규칙을 "모두 seed 42 기준" 또는 "모두 평균 기준"으로 통일하고, 표에 각 값의 기준선을 적는다.
  - McNemar 검정은 대조군을 고정값으로 보므로 seed 분산이 빠져 있다는 점도 적는다.
- **"A가 최고"는 선택의 결과다.** 세 설정 중 dev 최고를 고른 것이다. 차이가 유의하지 않으므로 "A, B, C는 같은 수준이고, 판정 비용이 없어서 A를 채택한다"로 고친다. 해석 1(출처 3/4)과 해석 2(Arctic-Embed와 맞음)도 가설로 내린다. 해석 3(A·B 실패 유형 ±22)은 검정하지 않은 수치이고 seed 잡음 규모(질문 60~70개)보다 작다.
- **epoch 선택 편향.** 보고하는 dev에서 best epoch를 골랐다. 대조군에도 같은 규칙을 적용했으므로 Δ에 대한 편향은 작다. 그래도 0.761이라는 절대값은 낙관적이다. 민감도 확인으로 "epoch 4 고정" 값을 함께 보고한다. 간이 지표 기준으로 A 0.744, 대조군 0.709이고 Δ는 여전히 약 +0.035다.
- **간이 지표와 공식 지표를 표에서 구분한다.** epoch 표는 간이 지표이고, 대조군도 공식 지표와 약 0.011 차이가 난다. 표 제목에 명시한다.
- **학습 질문 81개 제외**는 A에 불리한 방향이므로 결론을 위협하지 않는다. 다만 계획에 없던 차이로 기록한다. exp_009 대비 +0.032는 스케줄이 다른 run과의 비교라서 참고값으로만 쓴다.

## 2. 다음 실험들의 dev 재사용 안전장치

1. **dev 사용 장부** `runs/ledger.tsv`: dev를 평가할 때마다 한 줄씩 남긴다(run, config 해시, 확증·탐색 여부, R@5, 채택 여부). 결과에는 "지금까지 dev에서 N개 설정을 봤다"를 함께 적는다.
2. **val2는 지금 만든다.** 002는 기준 모델(A)과 대조군을 어차피 다시 학습하므로 비용이 가장 싸다. train 법령 3~4개(약 900문항, 세법 하나 포함)를 떼어 epoch 선택과 변형 탐색에 쓴다. dev는 단계마다 확증 비교 3개 이하에만 쓴다.
3. **seed 정책.** 확증 run은 기본 2 seed로 한다. Δ < 0.03이면 3 seed로 늘린다. seed SD는 질문별 뒤집힘으로 추정한다.
4. **test 사용.** 최종 모델을 고정한 뒤 한 번만 쓴다. 그 전에 test 분석 계획(대조 대상, 법령 군집 bootstrap, 법령 평균)을 커밋해 둔다. dev와 test의 차이(Gemma에서 0.013 대 0.074)를 볼 때 test 하락을 예상해 둔다. 결정 A·B 때문에 중간 확인이 필요하더라도 test 대신 val2를 쓴다.

## 3. 과정 개선

- **사전 등록 템플릿** 항목: 가설, 주 지표, 확증 비교 목록과 비교별 기준선, 검정 통계, α와 Holm family, 효과 임계값, seed 정책, epoch 선택 규칙, 예외 처리(negative 0개 질문 등), 분기 규칙, 비용 상한, 커밋 해시
- **decision.json 형식**: schema 버전, 계획 커밋, family 목록. 비교마다 기준선 run id, Δ, CI, 원래 p와 Holm p, seed SD, 기준별 통과 여부, 최종 판정. run마다 학습 행 수, best epoch, 간이 값과 공식 값, epoch 고정 민감도
- **자동화**: `ragkit compare <plan.yaml>`이 paired test, Holm, decision.json, ledger 추가를 한 번에 한다. 평가 전에 라벨·split 해시가 digest와 같은지 검사한다. manifest 단계에서 negative 0개 질문을 경고한다. 간이 지표를 공식 지표와 같은 방식(partial 제외)으로 맞춘다.
- **판정 비용 관문**: 회고 제안에 동의한다. 판정 표본 수백 쌍으로 짧게 학습해 비교한 뒤 전체 판정 여부를 정한다.
