# 법령 질문 생성

임베딩 파인튜닝 강의용 데이터를 만든다. 검색 대상은 대한민국 법령 조문(`data/processed/law_docs.json`, 조문 약 1.2만 개를 문서 약 2.6만 개로 나눈 것)이고, 이 스킬은 "사람이 실제로 검색창에 칠 법한 질문 → 그 질문에 답하는 조문" 쌍을 만든다.

이 데이터의 목적을 기억하면 대부분의 판단이 쉬워진다. **베이스 임베딩 모델이 어려워하는 질문**을 만들어야 파인튜닝 효과가 드러난다. 베이스 모델은 질문과 조문에 같은 단어가 있으면 이미 잘 맞힌다. 약한 곳은 일상 표현("알바", "잘렸어요", "딱지")과 법률 용어("근로자", "해고", "범칙금") 사이의 어휘 차이다.

## 작업 단위: 파트 하나 = 작업 하나

법령은 조문 순서대로 약 4만 자씩 **파트**로 나뉜다(전체 약 232개). 파트 하나를 읽고, 질문 파일 하나를 쓰고, 검증을 통과시키면 작업 하나가 끝난다. 법령 전체를 한 번에 처리하지 않는 이유는 출력 한도, 품질 유지, 실패 시 재시도 비용 때문이다. 여러 파트를 맡았다면 파트마다 아래 흐름을 반복하고, 파트가 많으면 서브에이전트에게 파트 단위로 나눠 준다(각 에이전트에게 법령 이름, 파트 번호, 이 SKILL.md 경로를 넘긴다). 여러 작업이 동시에 돌 수 있으므로, `show` 출력을 저장하거나 생성 스크립트를 만드는 임시 파일은 `p1.txt` 같은 흔한 이름이 아니라 법령·파트가 들어간 이름(예: `도로교통법__p01_show.txt`)으로 만든다. 다른 작업이 같은 파일을 덮어쓰면 엉뚱한 법령으로 질문을 만들게 된다.

스크립트는 모두 프로젝트 루트에서 실행한다.

```bash
S=.claude/skills/law-question-gen/scripts
```

## 작업 흐름

1. **진행 상황 확인**: `uv run python $S/law_parts.py list [--theme youth]`
   법령별 조문 수, 파트 수, 완료 파트 수를 보여 준다. 법령 이름은 여기 나온 이름(코퍼스의 `category`)을 그대로 쓴다. 사용자가 법령만 말하고 파트를 말하지 않았다면 파트가 1개인 법령은 그 파트를, 여러 개인 법령은 전체 파트를 처리할지 사용자 의도를 따르고, 애매하면 파트 1부터 한다.

2. **파트 읽기**: `uv run python $S/law_parts.py show <법령> --part N`
   조문 전체와 출력 파일 경로가 나온다. 출력이 길어도 **끝까지 모두 읽는다.** hard negative를 고르려면 파트 안의 다른 조문들을 알아야 한다. 한 법령 폴더에는 법률·시행령·시행규칙이 함께 들어 있어서 id가 `최저임금법_법률_제5조`, `최저임금법_시행령_제3조`처럼 다르다.

   임베딩 모델이 512토큰까지만 읽기 때문에 긴 조문은 **항 단위로 나뉘어** 있다(`최저임금법_법률_제6조_제1항`, `…_제6조_제4항`). 항이 여전히 길면 호 묶음으로 더 나뉜다(`도로교통법_법률_제2조_제1~19호`). 이런 조각 하나하나가 검색 문서다. 질문의 답이 들어 있는 **그 조각의 id**를 정답으로 쓴다. 조 전체를 가리키는 id는 코퍼스에 없다.

3. **질문 파일 쓰기**: `data/questions/<법령>__pNN.jsonl` (show가 알려 준 경로. 사용자가 다른 폴더를 지정하면 그 폴더에 **같은 파일 이름**으로 쓴다. 검증 스크립트가 파일 이름에서 법령을 읽는다.)

4. **검증**: `uv run python $S/validate_questions.py <파일>`
   `ERROR`가 0개가 될 때까지 고친다. `WARN`은 읽어 보고 타당하면 고친다. 마지막 통계(유형 분포, 법령 이름 포함 비율)가 아래 목표에서 크게 벗어나면 질문을 손본다.

   여러 파트를 끝냈다면 마지막에 `validate_questions.py data/questions/*.jsonl`로 **모든 파일을 한 번에** 검사한다. 파일 사이에 같은 질문이 있으면 오류로 잡힌다. 예를 들어 "청년 나이 기준"은 청년기본법과 청년고용촉진특별법에서 답이 다르다. 이런 질문은 법령의 맥락이 드러나게 고친다.

5. **보고**: 파일 경로, 질문 수, 정답 조문 수, 유형 분포, 건너뛴 조문의 성격(예: "위원회 구성·운영 조문 12개 건너뜀")을 짧게 알린다.

## 출력 형식

JSONL, 한 줄에 레코드 하나. UTF-8 그대로 쓴다(`\uXXXX` 이스케이프 없이).

```json
{"query": "편의점 알바 수습 기간이라고 시급을 최저임금보다 적게 준대요. 이거 되는 거예요?", "positive_id": "최저임금법_법률_제5조", "hard_negative_ids": ["최저임금법_법률_제6조", "최저임금법_법률_제7조"], "query_type": "situation", "answer": "1년 이상 계약한 수습 근로자는 수습 시작 후 3개월 이내라면 최저임금과 다른 금액을 정할 수 있습니다. 다만 단순노무직으로 고시된 직종은 예외라 감액할 수 없습니다."}
```

| 필드 | 설명 |
|---|---|
| `query` | 검색 질문 |
| `positive_id` | 질문에 답하는 문서(조문 또는 항·호 조각) id. `show` 출력의 `=== ` 뒤 문자열을 그대로 복사한다 |
| `hard_negative_ids` | 1~3개. 아래 기준 참고 |
| `query_type` | `situation`, `question`, `keyword` 중 하나 |
| `answer` | 정답 조문만 근거로 한 한두 문장 답. 나중에 RAG 답변 평가의 기준 답으로 쓴다 |

## 질문 쓰는 원칙

### 1. 일상 표현으로 묻는다

법률 용어를 질문에 그대로 옮기면 베이스 모델도 단어 일치로 쉽게 맞혀서 파인튜닝 효과가 사라진다. 조문의 용어를 질문자가 실제로 쓸 말로 바꾼다.

- 조문: "사용자는 … 최저임금액 이상의 임금을 지급하여야 한다" → 질문: "사장님이 시급 8천원 준다는데 이거 불법 아니에요?"
- 조문: "운전면허를 받지 아니하고 원동기장치자전거를 운전한 사람" → 질문: "면허 없이 전동킥보드 타다 걸리면 어떻게 돼요?"

용어를 다 피할 필요는 없다. 일반인도 흔히 쓰는 말(최저임금, 월세, 음주운전)은 써도 된다. 피할 것은 조문에만 나오는 딱딱한 표현(원동기장치자전거, 소정근로시간, 과세표준)을 그대로 베끼는 것이다.

### 2. 질문자를 테마에 맞춘다

`show` 첫 줄에 테마가 나온다. 실제로 그 법을 검색할 사람을 떠올리고 그 사람의 상황과 말투로 쓴다.

| 테마 | 질문자 |
|---|---|
| youth | 학생, 알바생, 사회초년생, 자취생, 첫 직장인 |
| traffic | 운전자, 초보 운전자, 킥보드·자전거 이용자, 보행자 |
| tax | 직장인(연말정산), 프리랜서, 자영업자, 집 사고파는 사람 |
| finance | 직장인, 대출·카드·투자하는 개인, 소상공인 |
| consumer | 온라인 쇼핑·할부·렌탈·배달 이용 소비자 |
| electric | 전기 기술자, 전기공사업자, 설비 관리자 (이들은 업계 용어를 쓰므로 용어를 더 써도 자연스럽다) |

### 3. 유형을 섞는다

목표 비율은 대략 situation 40%, question 25%, keyword 35%다. 실제 검색어는 2~3어절 명사 묶음이 가장 많아서(3-1 참고) keyword 비중을 높게 잡았다. 실제 검색 쿼리는 다양하고, 평가셋도 그래야 모델이 한 가지 말투에만 맞춰지지 않는다.

- **situation**: 자기 상황을 설명하며 묻는다. "3개월 일하고 그만뒀는데 사장님이 마지막 달 월급을 안 줘요"
- **question**: 상황 없이 궁금한 점을 묻는다. "수습 기간에도 최저임금 다 받아야 하나요?"
- **keyword**: 검색창에 치는 짧은 키워드. "수습 최저임금 감액", "킥보드 면허 벌금". 이 유형만 용어를 좀 더 써도 된다.

### 3-1. keyword·question 형식 few-shot

실제 검색어는 문장보다 **2~3어절 명사 묶음**이 훨씬 많다. KoAIO 검색어 7천여 개를 분석해 보니 명사구 계열이 약 70%였고, 그중 70%가 2~3어절이었다(분석 근거: `references/query-style.md`). keyword와 question 질문을 쓸 때는 아래 형식을 고루 섞는다. 가운데 열은 **형식만** 참고하라고 붙인 KoAIO 원문이다. 내용(보험, 윈도우, 의학)은 따라 하지 않는다.

| 형식 | KoAIO 원문 (형식 참고용) | 우리 데이터 예 |
|---|---|---|
| 주제 + 주제 (2~3어절) | 종신 보험료, 장외 주식 | 음주운전 면허취소, 알바 주휴수당 |
| 주제 + 꼬리어 | 저나트륨혈증 원인, 압력 단위 변환 | 주휴수당 조건, 퇴직금 계산, 연차 발생 기준 |
| A와 B 차이 | 스시와 사시미 차이 | 벌금 과태료 차이, 권고사직 해고 차이 |
| ~하는 방법 / ~하는 법 | 두통 없애는 방법 | 밀린 월급 받는 방법, 부가세 신고하는 법 |
| ~하기 | 구글 메일 계정 만들기 | 종합소득세 직접 신고하기 |
| 상태 서술 (~안 함, ~됨) | 전화기 충전 안됨 | 퇴사했는데 퇴직금 안 줌 |
| 조건 파편 (~하면) | 세상에 100명이 있다면 | 음주측정 거부하면, 알바 하루 빠지면 주휴수당 |
| ~하는지 | 골수 기증 절차 어떻게 하는지 | 자진퇴사 실업급여 받을 수 있는지 |
| 짧은 정의 질문 | 복부 성형이란 무엇인가 | 통상임금이란, 가산세가 뭐예요 |
| 얼마·언제 (물음표 생략) | 삼차신경통은 얼마나 흔한가 | 킥보드 헬멧 안 쓰면 벌금 얼마, 연말정산 서류 언제까지 |
| 짧은 ~나요 | 말벌이 쏘나요 | 수습도 4대보험 되나요 |

- 꼬리어로는 **기준, 조건, 방법, 계산, 차이, 뜻, 벌금, 기간, 서류, 대상, 신고**를 돌려 쓴다. 한 파트에서 "~ 기준"만 반복하지 않는다.
- 1어절 쿼리("면허", "근로자")는 정답 조문 하나를 정할 수 없으므로 쓰지 않는다.
- KoAIO의 "~해야 할까?" 토론형 질문과 "무엇인가 / 하는가" 같은 번역체 어미는 가져오지 않는다. 정의 질문은 "~란", "~뜻", "~뭐예요"처럼 한국 사람이 실제로 치는 말로 쓴다.
- 위 표의 형식은 `query_type` 분류를 바꾸지 않는다. 명사 묶음, "~하기", 상태 서술, 조건 파편은 `keyword`로, "~하는지", 짧은 정의 질문, 얼마·언제 질문, "~나요" 질문은 `question`으로 표시한다.

### 4. 조문 번호는 쓰지 않고, 법령 이름은 가끔만 쓴다

"제N조"가 들어가면 정답을 알려 주는 셈이라 검증에서 오류가 난다. 법령 이름("최저임금법에서…")도 사람들이 실제로는 잘 안 쓰고, 넣으면 검색이 쉬워지므로 전체의 약 20% 이하로만 쓴다.

### 5. 그 조문(조각) 하나로 답할 수 있어야 한다

질문의 답이 정답 문서에 들어 있어야 한다. 항 조각이라면 그 항 안에 답이 있어야 한다. 예를 들어 "제1항에 따른 금액"처럼 다른 항을 가리키기만 하는 항은 그것만으로 답할 수 없으면 정답으로 삼지 않는다. 조문에 없는 금액·기간·조건을 지어내지 않는다(예: 조문이 "대통령령으로 정하는 금액"이라고만 하면 "얼마예요?"라고 묻는 질문의 정답이 될 수 없다. 그 금액이 적힌 시행령 조문이 같은 파트에 있다면 그 조문을 정답으로 삼는다). 질문 속 구체적 설정(편의점, 3개월 등)은 자연스럽게 지어내도 되지만, 답이 그 설정에 따라 조문 밖 사실에 좌우되면 안 된다.

`answer`도 정답 조문에 적힌 내용만으로 쓴다. 조문이 다른 조문이나 시행령에 위임하면 "구체적인 기준은 대통령령으로 정한다"처럼 위임 사실을 그대로 말한다.

## 조문별 질문 수: 0~3개

조문마다 사람들이 실제로 검색할 만큼 중요한지 판단한다. 모든 조문에 기계적으로 질문을 붙이면 아무도 검색하지 않을 행정 조문 질문이 데이터를 채워 학습 신호가 흐려진다.

| 조문 성격 | 질문 수 | 예 |
|---|---|---|
| 권리·의무·금액·기간·금지 | 2~3 | 최저임금 지급 의무, 수습 감액, 면허 취소 기준, 청약 철회 기간 |
| 적용 범위·정의·예외 | 1~2 | "가족끼리 하는 가게도 최저임금 적용돼요?" |
| 벌칙·과태료 | 상황형 1 | "신호위반하면 벌금 얼마예요?" |
| 절차·신고·서류 | 0~1 | 일반인이 직접 하는 절차면 1, 행정기관 내부 절차면 0 |
| 목적, 위원회 구성·운영, 권한 위임, 공무원 의제, 준용 | 보통 0 | |
| `[LOW-VALUE]` 표시 조문 | 보통 0 | 스크립트가 미리 표시한 저가치 조문 |

시행령·시행규칙 조문도 같은 기준으로 본다. 구체적인 금액·비율·기간이 적힌 시행령 조문은 오히려 좋은 정답이 된다.

파트 전체로 보면 조문당 평균 1~1.5개 정도가 된다. 행정 조문이 대부분인 법령(공제조합법 등)은 훨씬 적어도 괜찮다. 억지로 채우지 말고, 건너뛴 이유를 보고에 적는다.

## Hard negative 고르기

hard negative는 "주제는 비슷해서 검색 결과에 같이 뜰 만하지만, 이 질문에는 답하지 못하는 조문"이다. 모델이 비슷한 조문 사이의 미세한 차이를 배우게 하는 핵심 데이터다.

- **같은 파트 안에서** 고른다(파트 안의 조문만 읽었으므로 판단이 정확하다).
- 좋은 예: 수습 감액 질문 → 최저임금의 효력(지급 의무) 조문, 적용 제외 조문. 주제(최저임금)는 같지만 수습 감액에 대한 답은 없다.
- 피할 것: **정답이 될 수도 있는 조문.** 같은 내용을 구체화한 시행령·시행규칙 조문(예: 법률 제5조 수습 감액 ↔ 시행령의 감액 비율 조문)은 질문에 부분적으로 답하므로 negative로 쓰면 모델에 틀린 신호를 준다. 판단이 애매하면 빼고 확실한 것만 넣는다.
- 같은 조의 다른 항 조각은 좋은 hard negative가 될 수 있다(예: 최저임금 지급 의무 항 ↔ 산입 범위 항). 다만 질문의 답이 두 항에 걸쳐 있으면 그 항은 negative로 쓰지 않는다. 한 질문의 답이 여러 조각에 흩어져 있다면 한 조각만으로 답할 수 있게 질문 범위를 좁힌다.
- 피할 것: 주제가 전혀 다른 조문. 너무 쉬워서 학습 효과가 없다.
- 1~3개. 좋은 후보가 하나뿐이면 하나만 넣는다.

## 자주 하는 실수

- `positive_id`를 손으로 타이핑하다 틀림 → `show` 출력의 id를 복사한다. 검증 스크립트가 코퍼스에 없는 id를 잡아낸다.
- 질문이 조문 문장을 의문문으로 바꾼 수준 ("사용자는 최저임금액 이상의 임금을 지급하여야 하나요?") → 질문자의 상황과 말로 다시 쓴다.
- 같은 조문에 거의 같은 질문 세 개 → 질문 여러 개를 쓸 때는 조문의 서로 다른 항이나 서로 다른 상황을 겨냥한다.
- 파트 앞부분만 꼼꼼하고 뒤로 갈수록 대충 → 뒷부분(벌칙, 시행령)에도 좋은 조문이 많다.
